# vngrd-kernel

Builds the vngrd Linux kernel with LLVM/clang and publishes the artifact for [vngrd-image](../vngrd-image).

**Version contract:** `version` must match `vngrd-rootfs/packages/linux-headers/version`.

## Requirements

- x86-64 Linux host
- Docker or Podman

## Usage

```bash
./scripts/build.sh
# -> ../output/kernel/{boot/vmlinuz,boot/config,usr/lib/modules/<kver>/}

# import an existing kernel tree or tarball with the same shape
./scripts/build.sh --prebuilt /path/to/kernel-tree-or.tar.gz

# remove caches and the published artifact
./scripts/clean.sh
```

The first build creates the builder image. Kernel compilation runs in that container; the host only needs Docker.

## Configuration

`configs/vngrd.config` is the source of truth for every kernel decision. It is a named Kconfig fragment merged onto the generated `kernel.config` by `scripts/build-inner.sh`.

Do not hand-edit `kernel.config`; it is regenerated by `olddefconfig`. Edit the fragment and rebuild.

The build fails on unknown symbols, fragment values Kconfig did not honour, missing lockdown or module-disable settings, and a kernel linked by anything other than LLVM `ld.lld`.

## Layout

```
version sources checksums    kernel release and source
configs/vngrd.config         configuration fragment
kernel.config                generated base config (input to the merge)
docker/                      builder container
scripts/build.sh             fetch, build, publish
scripts/build-inner.sh       configure, verify, make (inside container)
scripts/clean.sh             clean caches and output
out/ work/ cache/            build state (gitignored)
```

## Artifact shape

```
../output/kernel/
├── boot/vmlinuz
├── boot/config
└── usr/lib/modules/<kver>/
```

`vngrd-image` reads this tree through mkosi `BaseTrees=`.
